# VoltPassport v1 — отдельная ветка

## Что это

Цифровой паспорт **со слов продавца** и личная проверка покупателя в две колонки. Сейчас реализована категория «смартфон» (11 проверок, как в VoltCheck). Для мебели/ноутбуков можно добавить другие наборы проверок позже, после реального теста.

### Проверяемое отличие от обычного объявления

- У каждого объявления появляется кнопка «Паспорт состояния».
- Продавец может отметить состояние 11 узлов, добавить краткое пояснение, сохранить на сервер (после отдельного внедрения SQL).
- Покупатель видит дату изменения и пометку «со слов продавца», ставит свои отметки и получает список расхождений.
- Отметки покупателя **не отправляются на сервер** и живут только в `sessionStorage` текущей вкладки.
- Отметки из VoltCheck, сделанные **в той же вкладке** для того же объявления, подхватываются автоматически при открытии VoltPassport. В других вкладках/устройствах данные не синхронизируются.
- Нет рейтинга доверия, сертификата, гарантий, автоматической проверки IMEI или подтверждения личности.

## Безопасный пробный запуск

После публикации статических файлов откройте `voltpassport.html?demo=1` — это **отдельный демонстрационный режим**, он не создаёт запись в Supabase. Его можно использовать и локально через `file://`, если все файлы лежат рядом.

**Обработка в реальном режиме без SQL:** если в базе не создана `ad_passports`, страница должна показать предупреждение и заблокировать запись. Она не будет изображать, будто паспорт опубликован.

## Подключение реальной БД (перед выпуском, не выполнено)

1. Сначала получите действующий `supabase/schema.sql` или прочитайте структуру *именно VoltStore-проекта* в Supabase. Исходная полная схема отсутствует в ветке `main`.
2. Проверьте статус законности текущего хранения данных (Казахстан), права пользователей, доступ к таблице `ads`.
3. Прочитайте `supabase/voltpassport_schema_draft.sql`; это проект SQL, **не выполненный на рабочей базе**. В качестве FK сознательно не использован `ad_id`, пока неизвестен тип `public.ads.id`.
4. На отдельной тестовой базе выполните SQL и проверьте политики RLS: anon/owner/другой продавец/banned user/проданное объявление.
5. После успешного тестирования согласуйте применение миграции к рабочей базе. Только после этого рассматривайте объединение PR в `main`.

## Локальные проверки

`node --test tests/voltpassport-core.test.cjs`

`node --check passport-core.js` и `node --check passport-app.js`

Проверить вручную:
- `voltpassport.html?demo=1`: открыть, выбрать статусы, оставить пояснения, сохранить, обновить страницу и сравнить;
- `voltpassport.html?demo=1&ad=demo123`: убедиться, что локальное хранилище не смешивается с другим `ad`;
- начать VoltCheck в той же вкладке и вернуться «Назад»;
- на узком мобильном экране, с клавиатуры и в режиме печати;
- без таблицы в Supabase публичный режим должен быть только для чтения;
- в новом браузере нельзя редактировать чужой паспорт.

## Ограничения

Продавец может изменить данные своего паспорта после размещения объявления, история версий пока не хранится. Не полагайтесь на паспорт для взысканий или сертификации. Ранее существовавшая модерация объявления не является проверкой сведений паспорта. Нет автоматического удаления паспортов вслед за удалением объявления. Для коммерческого запуска эти вопросы требуют решений.
