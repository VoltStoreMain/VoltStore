# VoltStore QA: Playwright E2E + Lighthouse CI

Эта система тестирует независимую предпросмотр-версию **только в GitHub Actions**. Она не подключается к платным AI-сервисам, не проводит платежи, не использует производственные Supabase-данные и не разворачивает сайт в Netlify.

## Запуск
GitHub Actions → **VoltStore browser E2E & Lighthouse**. Автоматически запускается на push в feature/ci-playwright-lighthouse и при изменении соответствующих файлов в Pull Request. После успешного внедрения для постоянной проверки следующих PR необходимо добавить этот workflow в основную ветку проекта (только после проверки и согласованного слияния).

## Playwright
- Реальные браузерные движки на GitHub runner: Chromium (1280 px), Chromium с мобильной эмуляцией Pixel 7, WebKit с эмуляцией iPhone 13. **Это не тест на физических устройствах**.
- Функциональные сценарии: каталог/категории/фильтры, отсутствие горизонтальной прокрутки, открытие конкретного товара и VoltDeal, полный учебный цикл покупатель→продавец→покупатель→продавец, обязательные подтверждения, загрузка локального фото, галерея, перезагрузка/удаление черновика, бесплатный VoltGuide.
- Отдельно в Chromium: PWA service worker, контроллер, кеш только статических ресурсов и переход в офлайн-каталог.
- Ошибки сохраняются как трассы, видео и скриншоты. Даже при успешных тестах сохраняются снимки каталога и завершённой демо-сделки.
- Сервер предпросмотра — локальный `python3 -m http.server 4177 --bind 127.0.0.1` внутри GitHub Actions.

## Lighthouse CI
- Проверяет мобильные `market.html`, `voltdeal.html?ad=demo-phone-1`, `voltguide.html?category=laptop` на локальном 127.0.0.1.
- Производительность и доступность измеряются, вначале устанавливаются консервативные пороги для обнаружения критических проблем (performance ≥ 0.70, accessibility ≥ 0.90, CLS ≤ 0.25, LCP ≤ 3500 мс). После реального baseline пороги нужно усилить: низкие значения **не означают, что сайт достаточно быстр**.
- Результаты HTML/JSON сохраняются в приватном artifact GitHub Actions; **не отправляются во временное публичное хранилище**.
- Колебания Lighthouse возможны из-за CI-машины. Для сравнения до/после фиксируйте конфигурацию и сравнивайте несколько запусков, а не один случайный балл.

## Отчёты
Откройте Actions → последний запуск **VoltStore browser E2E & Lighthouse** → раздел Artifacts:
- `voltstore-playwright-...`: скриншоты, trace.zip, видео/HTML и JUnit (в зависимости от результата).
- `voltstore-lighthouse-...`: JSON/HTML Lighthouse (для измерений и сравнения).

## Локально
Требуется Node.js 22+, Python 3 и установка браузеров Playwright:

```bash
npm install --no-audit --no-fund
npx playwright install chromium webkit
npm run test:e2e
```

Для Lighthouse в отдельном терминале запустите `python3 -m http.server 4178 --bind 127.0.0.1`, затем `npm run test:lighthouse`.

## Важные ограничения
- Тесты проверяют демонстрационную цепочку PR #2 → #3 → #4 → #5 → #6 → #7 → #8 → этот PR. Не тестируют реальную оплату, настоящий заказ, модерацию или RLS рабочей базы.
- Никакие приватные секреты не используются. GitHub Actions может расходовать лимиты минут CI в соответствии с условиями вашего тарифного плана.
- Браузерное E2E не заменяет ручное тестирование на настоящих Android/iPhone, проверки доступности со скринридером и проверку производительности реального HTTPS-сайта.
- Версии Playwright и Lighthouse зафиксированы в package.json; workflow использует npm install без lockfile. Для production желательно создать и проверять package-lock.json, перейти на npm ci.
- Ни одна ветка не объединяется с main автоматически.

## Результат реального QA
Первый запуск выявил две браузерные проблемы, не видимые статическим тестам: первоначальная активация Service Worker перезагружала незавершённую форму, а WebKit отказывался хранить JPEG Blob в IndexedDB. Оба сценария исправлены в ветке: PWA не перегружает страницу без явного обновления; фото хранятся как ArrayBuffer (с чтением старых Blob-записей). Проверки остаются обязательными для последующих изменений.

## Подтверждённый локальный baseline (GitHub Actions, 22 ноября 2026)
После исправления ошибки первого Service Worker и WebKit IndexedDB, а также стабилизации мобильных фильтров:
- Unit/integration: 129/129.
- Playwright: 19 успешно выполненных E2E-сценариев в Chromium Desktop, Android Chromium и iPhone WebKit; 2 проверки Service Worker намеренно пропущены на WebKit, где они не относятся к целевой проверке.
- Lighthouse в локальном мобильном режиме: VoltMarket performance 88–93, accessibility 100, CLS 0.157; VoltDeal performance 97, accessibility 100, CLS 0.101; VoltGuide performance 100, accessibility 100, CLS 0. Это не показатели production-сайта.
- Выявленные и исправленные регрессии: неожиданная перезагрузка при первой активации PWA; сбой хранения Blob в WebKit IndexedDB (замена на ArrayBuffer с совместимостью чтения старых записей); поздняя вставка категорий, фильтров и уведомлений с сильным CLS.
- Теперь минимальные пороги в Lighthouse CI обеспечивают fail статуса при performance ниже 70, accessibility ниже 90, CLS выше 0.25 или LCP выше 3500 мс; показатели могут колебаться между CI-запусками.
