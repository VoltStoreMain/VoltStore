# VoltStore — приоритеты работы AI-команды

Актуальная схема задач для начала vibe working. Конкретные Issues остаются единственным источником статусов работ; этот файл задаёт приоритеты, а не утверждает выполнение.

## P0 — выпуск без риска
1. **Release train #2–#9:** провести обзор зависимостей, подготовить порядок слияния/альтернативу объединению в одну review-ветку, проверить конфликты, провести QA перед production. Никаких автоматических merge.
2. **Production Supabase audit:** подтвердить идентичность проекта, историю миграций, RLS, Storage, права seller/buyer/moderator, регион хранения и соответствующие обязательства. Без изменений данных на этом этапе.
3. **Device QA:** реальные Android Chrome и iOS Safari, фото/HEIC, PWA home-screen, авторизация (в безопасном тестовом окружении), экранная клавиатура, крупный шрифт, плохое соединение.
4. **Honest commerce states:** live VoltResale/заказы отдельно от VoltDeal demo; запрет ложных «оплачено», «проверено» и «забронировано».

## P1 — рабочая универсальность
5. Реальные объявления универсальных категорий: свойства, поиск, хранение фотографий, модерация, миграция старых смартфонов.
6. Настоящая серверная заявка/бронь: атомарность, auth, rate limits, idempotency, статус товара, уведомления, лог, отмена, защита двойной продажи.
7. Покупатель и продавец: обратная связь после реальных пользовательских тестов, внедрение ключевых исправлений, аналитика без лишних персональных данных.

## P2 — после подтверждения спроса
8. Платёжный партнёр и договорная модель расчётов после правовой оценки.
9. AI-помощник с явным согласием, контролем расходов, privacy и отказоустойчивыми бесплатными подсказками.
10. Расширение каталога, доставка и партнёры после проверки спроса.

## Definition of done
Issue с критериями принятия → маленький draft PR → тесты + отчёт о рисках → review → preview на телефоне → явное одобрение владельца. Любое «готово» без этих шагов = прототип, а не production.
