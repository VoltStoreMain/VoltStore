# VoltDeal v1 — демонстрационное оформление сделки

Ветка: feature/voltdeal-buying-flow, построена поверх PR #5. Не опубликована в main.

## Покупатель
1. Открывает товар из VoltMarket и нажимает «Попробовать оформление».
2. Выбирает предпочтительный формат встречи / обсуждение доставки и время. Явно соглашается, что демо не является реальной бронью.
3. Продавец в учебной роли подтверждает или отклоняет заявку.
4. Покупатель открывает VoltCheck с контекстом того же товара, отмечает результат осмотра. Известный критический дефект нельзя отобразить как беспроблемный результат без исправления личных отметок.
5. Покупатель вручную подтверждает получение в демо. При отмеченных дефектах требуется дополнительное осознанное подтверждение риска.
6. Продавец отдельно подтверждает передачу, после чего заявка отмечается завершённой в учебном сценарии. **Не означает оплаты.**

## Продавец
Может подтвердить, отклонить или отменить заявку, отдельно подтвердить передачу после покупателя. Не может завершить процесс единолично. Переключатель ролей — только инструмент для демонстрации, не настоящая авторизация.

## Реализовано
- Отдельная адаптивная страница VoltDeal, связанная с выбранным товаром.
- Чистая модель состояний, допустимых действий по ролям и история этапов.
- Заявки хранятся только в localStorage текущего браузера, результаты VoltCheck — в sessionStorage.
- Подсказки безопасности, отказ от предоплаты незнакомцам, демо-памятка TXT.
- Нет платежей, доставки, настоящих сообщений, реального бронирования, работы с Supabase, платных AI-запросов.
- Не собираются ФИО, телефон, адрес, документы, карты или полный IMEI. Демо-страница имеет noindex.

## Перед продакшеном
P0: восстановить и проверить реальную схему Supabase VoltStore, регион хранения данных и соответствие требованиям обработки персональных данных Казахстана.

P0: создать серверные сущности покупателя, продавца и бронирования с RLS, серверной проверкой ролей, статуса модерации и прав. Реализовать атомарное бронирование экземпляра, ограничение числа активных заявок, idempotency и управляемое сервером истечение времени брони.

P0: добавить уведомление продавца, защиту переписки, отмены, журнал аудита, полную проверку каждого перехода статуса, нагрузочные и мобильные E2E-тесты.

P0: оплату напрямую при встрече никогда не показывать как оплату, подтверждённую VoltStore. Онлайн-платежи — только с договором и серверными вебхуками подходящего платёжного провайдера. Escrow/удержание средств третьих лиц — отдельный юридически проверенный процесс с партнёром.

P1: подтверждённые профессиональные продавцы, интеграция доставки, разрешение споров и поддержка после сделки.
