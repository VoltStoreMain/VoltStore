# VoltStore QA: одна изолированная demo-сборка

QA проверяет существующий универсальный demo-сценарий. Новых баннеров, кнопок или разделов для этой инфраструктуры в интерфейсе нет. Владелец предпочитает простой сайт с фокусом на товарах и следующем шаге покупки; дополнительные инструменты следует раскрывать по месту.

## Граница сборки

`npm run build:preview` запускает `scripts/build-preview.mjs` и создаёт только `preview/` по явному списку ресурсов. Корневые исходники магазина остаются на своих местах.

- `preview/index.html` перенаправляет в Market, без старой регистрации и карточного checkout.
- `preview/config.js` генерируется с пустыми Supabase URL/ключом и отключённым paymentProvider. Рабочий config не копируется.
- `app.js`, `live.js`, старый `voltcheck.html`, SQL и Netlify Functions не входят в сборку.
- В копии Passport удаляется ненужное внешнее подключение Supabase SDK. Исходная страница реального приложения не меняется.
- В HTML добавляется CSP: скрипты и соединения только своего origin, изображения также data/blob, внешние формы запрещены. Для Vercel такие же ограничения и noindex задаются в сгенерированном `vercel.json`; `robots.txt` запрещает индексирование.
- Сохраняются четыре категории, локальные черновики, фотографии, Passport Demo, бесплатный Guide, Check Universal, VoltDeal Demo и офлайн-оболочка.

В архиве нет серверного хранилища объявлений, реальной брони или оплаты. Публичный backend не включается настройкой деплоя. Не размещайте live-файлы или функции в папке demo.

## Идентичность артефакта

`build-manifest.json` содержит source commit, признак незакоммиченных изменений, SHA-256 и размер каждого файла, общий digest. Абсолютные пути, время сборки и персональные данные не записываются. Одинаковые исходники дают одинаковые байты и manifest.

`npm run verify:preview` отклоняет другой source commit, пропавшие/лишние файлы, изменённые байты, неожиданный backend URL/credential и внешние script-теги. Проверка обнаруживает рассогласование артефакта; она не заменяет review кода и не является цифровой подписью.

## GitHub Actions

Workflow **VoltStore browser E2E & Lighthouse**:

1. `build` запускает Node tests и создаёт demo один раз.
2. Он экспортирует `voltstore-demo-<run_id>`.
3. Playwright и Lighthouse скачивают именно этот артефакт в `preview/`; повторной сборки в этих jobs нет.
4. Проверка digest выполняется перед сервером и после тестов. Оба сервера отдают только `preview/`, а не корень репозитория.
5. Сохраняются отдельные отчёты Playwright и Lighthouse. При ошибке downstream jobs сам артефакт остаётся доступным, но не считается прошедшим QA.

Workflow **VoltStore universal inspections** сохраняет доменные и синтаксические проверки. Отдельную альтернативную ZIP-сборку он больше не создаёт.

Изменения builder, tests и конфигураций QA включены в path filters. Изменения исходного магазина также запускают проверку demo; это не означает, что реальные auth/RLS/заказы магазина покрыты E2E. При включении workflow в main обязательные checks и политику path filters нужно согласовать отдельно. Автоматического merge или deploy нет.

Artifacts находятся в GitHub Actions и живут 7 дней. Не считайте их местом для секретов и персональных данных, особенно в публичном репозитории. Внешняя временная публикация отчётов Lighthouse не используется.

## Локальный запуск

Нужны Node.js 22+, Python 3, тестовые зависимости и браузеры:

```bash
npm install --no-audit --no-fund --package-lock=false
npx playwright install chromium webkit
npm run test:unit
npm run build:preview
npm run verify:preview
npm run test:e2e
npm run test:lighthouse
```

Playwright сам запускает сервер на 127.0.0.1:4177, Lighthouse — на 127.0.0.1:4178. Оба проверяют manifest до старта и обслуживают только `preview/`. Заранее поднимать сервер из корня проекта не нужно. Если порты заняты, освободите их; не подменяйте сервером рабочего приложения.

Для ручного локального осмотра:

```bash
npm run build:preview
python3 -m http.server 4179 --bind 127.0.0.1 --directory preview
```

Откройте `http://127.0.0.1:4179/`. Сборка не публикуется этой командой. Не запускайте `http.server` из корня проекта без `--directory preview` для demo QA.

## Что проверяет Playwright

- Chromium desktop, Android Chromium emulation, iPhone WebKit emulation. Это браузерные движки и эмуляция, не физические устройства.
- Каталог, категории, поиск, отсутствие горизонтального переполнения, конкретная карточка → VoltDeal, обязательные согласия и обе учебные роли.
- Локальные фото, галерея, перезагрузка/удаление черновика и бесплатные рекомендации.
- Вход через `/` ведёт в каталог; live-магазин, SQL и серверная функция отсутствуют; реальный Passport остаётся недоступным без базы; явное нажатие AI не подключает SDK/AI.
- Общий сетевой guard блокирует неожиданные внешние/API/auth-запросы и делает тест неуспешным при попытке. Проверки не отправляют данные в production. CSP дополнительно ограничивает соединения в самой сборке.
- В Chromium — офлайн-каталог, кеш без параметров товара и отсутствие перезагрузки незаполненной формы при первой активации SW. Эти два сценария пока пропускаются в WebKit.

Новые браузерные проверки добавлены к прежним семи сценариям: полный ожидаемый набор — 30 запусков, из них 28 passed и 2 намеренных WebKit skips при успешном CI. Это ожидаемая матрица, а не заявление о результате конкретного нового запуска; фактический статус смотрите по SHA в Actions.

## Lighthouse

Два мобильных прогона каждой страницы: Market, Deal с demo-phone-1, Guide с laptop. Пороги: performance ≥70, accessibility ≥90, CLS ≤0.25, LCP ≤3500 ms. HTML/JSON сохраняются для сравнения при одинаковых условиях. Замеры localhost CI не являются скоростью production/Vercel.

Исторический baseline до этой задачи: [run 44997847529](https://github.com/VoltStoreMain/VoltStore/actions/runs/44997847529), SHA `6664d442`. В JSON его artifact: Market performance 96/100, Deal 97/97, Guide 100/100; accessibility 100. Старые 129 Node tests и 19 browser passes / 2 skips относились к прежней матрице. Для новой сборки нужен отдельный результат.

## Открытые ограничения

- Эта задача изолирует сборку, но не исправляет потерю listing ID при переходе Guide/Universal Check → Passport. Не выдавайте общий пример за паспорт выбранной позиции.
- PWA install banner может перекрывать карточки на узком экране. Новые предложения установки и другие элементы в этой задаче не добавляются.
- Старый live fallback, серверные роли/RLS, Storage и рабочие сделки требуют отдельных задач. Production config и live.js здесь не меняются.
- Нужен физический Android/iPhone QA: клавиатура, крупный шрифт, HEIC, установка и обновление PWA, плохая сеть. Эмуляция его не заменяет.
- Версии инструментов зафиксированы напрямую, но транзитивные зависимости пока без lockfile. Перевод на npm ci — отдельное улучшение.

Выпуск, изменение production и подключение платных сервисов требуют отдельного согласия владельца.
