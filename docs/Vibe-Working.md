# VoltStore Vibe Working — рабочая система, а не отдельный платный сервис

**Статус:** настройка процесса в Draft PR. Самостоятельные автономные AI-исполнители, планировщик и платный API здесь не запускаются.

## Что подключено фактически
- GitHub: репозиторий `VoltStoreMain/VoltStore`, задачи Issues, версии Branches/PR.
- GitHub Actions: unit/integration, Playwright browser E2E (Chromium/Android emulator/WebKit iPhone emulator), Lighthouse CI с отчётами Artifacts.
- Vercel: отдельная демонстрационная HTTPS-версия без Supabase и реальных денежных операций.
- ChatGPT: анализ требований, исследование и координация через доступные подключённые инструменты. Для длинных многошаговых задач пользователь может отдельно запускать ChatGPT Work; здесь это **не включено автоматически**.
- Будущее: Figma — при необходимости согласованного дизайна; Supabase — только после подтверждения проекта, схемы, RLS и прав; платежный провайдер — после юридической и технической проверки.

## Один рабочий цикл
1. **Product owner** формулирует в свободном тексте пользовательскую проблему и ожидаемое поведение.
2. **AI-аналитик** переводит запрос в GitHub Issue: ценность, критерии готовности, риски, неясности, бюджет. При исследовании приводит ссылки на источники.
3. **AI-UX** предлагает мобильный маршрут и состояния: пусто, загрузка, ошибка, успех. До утверждения нет изменений рабочего интерфейса.
4. **AI-разработчик** читает `AGENTS.md`, делает изменение в изолированной ветке, открывает draft PR и описывает воздействие на безопасность и данные.
5. **Автоматическая QA** проверяет JS/доменные тесты, Android/iPhone-браузерные сценарии и Lighthouse; ссылки на логи и скриншоты прикладываются к PR.
6. **Ревью** проверяет доступы, мобильные сценарии и соответствие обещаний реальному поведению. При выявлении ошибки задача возвращается на исправление.
7. **Владелец проекта** лично проверяет HTTPS preview на телефоне и только после этого одобряет слияние/публикацию. Нет автоматического релиза без согласия.

Это **роли/этапы**, а не обещание, что сейчас работают четыре самостоятельных AI-бота. Подключённые приложения и GitHub CI позволяют применять процесс уже сегодня.

## Обязательные правила безопасности
- Нельзя писать/менять рабочую Supabase, Netlify production, продажи, платежи, RLS, Storage и AI-биллинг без отдельного согласия.
- Любые реальные объявления/паспорта/сделки нуждаются в серверной авторизации, проверке статусов, журнале аудита, лимитах и тестах ролей.
- Не разрешать AI нажимать «merge», «deploy production», «delete user data», «send payment» или рассылать клиентам сообщения без подтверждения.
- Код и поведение оцениваются по тестам и визуальной проверке, а не по заявлению агента «готово».
- Не копировать реальные телефоны, адреса, email, платежные данные, API-ключи в Issues и отчёты.

## Текущий блокер релиза
В открытых PR находится последовательность **#2–#9**, причём каждый следующий основан на предыдущем. Наличие зелёного CI на последней ветке не делает `main` готовым. Перед продакшеном нужно построить план последовательного слияния, проверить конфликтующие изменения и аудит реальной Supabase.

## Как запустить задачу в ChatGPT Work (действия пользователя)
Открой ChatGPT Work и поручение: «Открой GitHub `VoltStoreMain/VoltStore`. Прочитай AGENTS.md и docs/Vibe-Working.md в ветке, где они доступны. Возьми Issue №..., создай план, затем отдельную ветку и draft PR. Не сливай с main, не используй платные сервисы, не работай с production Supabase/Netlify. Запусти тесты и дай ссылки на preview и отчёты».

Работа в Work зависит от того, доступна ли функция в аккаунте, и от предоставленных прав к инструментам. Само наличие AGENTS.md не запускает агента по расписанию и не выдаёт права.
