# VoltStore Mobile First — UX implementation and validation

Ветка `feature/mobile-first-marketplace` построена поверх VoltDeal (PR #6). У проекта одна кодовая база для всех экранов, но интерфейс для ширины до 760 px оптимизирован специально для телефона.

## Что реализовано
- Общая мобильная нижняя навигация на пяти пользовательских экранах: VoltMarket, VoltDeal, VoltGuide, VoltCheck Universal, VoltPassport. Только работающие разделы: Каталог, Продать, VoltGuide, Проверка.
- На мобильной главной VoltMarket скрыт длинный маркетинговый блок, пользователь сразу видит категории и поиск. Пояснение о демонстрационных товарах и отсутствии настоящих сделок остаётся на виду.
- Категории: горизонтальная прокрутка одним пальцем с понятным выделением выбранной.
- Фильтры: поиск всегда виден, дополнительные поля по городу, состоянию, бюджету и свойствам категории доступны через раскрываемый блок; на десктопе они остаются раскрыты.
- Карточки: две в ряд на 320–760 px, с чётко читаемой ценой, состоянием, демо-статусом и крупной кнопкой действия.
- В карточке товара закреплена кнопка «Оформить · демо» и быстрый переход к личному осмотру VoltCheck; не требуется прокручивать страницу до блока покупки.
- VoltDeal: актуальная кнопка следующего действия закрепляется над нижней панелью. Она вызывает исходную кнопку/форму, не пропуская проверку обязательных полей и согласия. Учебные статусы не интерпретируются как оплата.
- Формы продавца, этапы сделки и переключатель ролей увеличены до удобных для нажатия размеров. Учтены safe-area отступы iPhone и режим reduced motion.
- Все функции сохраняют десктопное расположение; нет новой базы, платежных вызовов и платных API.

## Сценарии ручной проверки
1. 320/360/375/390/430 px: страница каталога без горизонтальной прокрутки. Ввод в поиск, фильтры, смена категории и открытие карточки.
2. Карточка товара: нижняя панель покупки и проверка. Перейти в VoltDeal и вернуться, убедиться в сохранении контекста товара.
3. VoltDeal: заявка → подтверждение продавца → осмотр → получение → передача. Попробовать отправить заявку без обязательного согласия: система не должна продолжить.
4. Отмена, отказ, дефекты, восстановление локальной истории после обновления.
5. iOS Safari и Android Chrome: нажатия, системная клавиатура, нижняя зона экрана, 200% увеличение текста и screen reader.
6. 768 и 1280 px: мобильные элементы отсутствуют, десктопный интерфейс и фильтры не нарушены.
7. Отключить хранилище браузера: приложение не должно ложно заявлять об успешной покупке.

## Что ещё не готово для production
- На настоящем сайте пока нет серверного бронирования, онлайн-оплаты или универсальных реальных объявлений.
- Текущие мобильные изменения накладываются поверх PR #6 → #5 → #4 → #3 → #2. Не сливать отдельный PR в main без проверки зависимостей.
- Обязательно отдельно пройти E2E на реальном iPhone и Android, проверить RLS/модерацию и правила обработки данных.
- Генеративный AI выключен по умолчанию, платных вызовов нет.
